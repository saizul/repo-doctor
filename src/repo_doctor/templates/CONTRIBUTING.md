## Making a change

1. Fork the repository and create a branch: `git switch -c fix/short-description`.
2. Make your change with tests where it makes sense.
3. Run the checks above and make sure they pass.
4. Update the documentation and `CHANGELOG.md` if users will notice the change.
5. Open a pull request and fill in the template. Link the issue it closes.

Keep pull requests focused: one fix or feature per pull request is easier to review.

## Commit messages

Use the imperative mood ("Add option", not "Added option") and explain *why*
in the body when it is not obvious.
